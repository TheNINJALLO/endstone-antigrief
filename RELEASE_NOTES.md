# AntiGrief 1.5.22

Remove routine container-access console spam and reduce repeated work when many players use containers. Opening containers, registering owners, capturing item changes, and caching legacy backups no longer emit routine console messages. Unauthorized activity remains in database/WebUI evidence; failures and rollback status remain visible.

Ownership and trust lookups use a 30-second cache capped at 2,048 containers. Placement and ownership/trust commands invalidate the affected entry immediately. Historical placement queries use a new coordinate/time index. Startup creates this index automatically; a large audit database can make the first startup longer.

Unchanged native revisions skip inventory diffing and duplicate closing snapshots. Slot comparisons copy only changed items, snapshot storage avoids redundant JSON conversions, and unchanged player inventories skip nested summaries. Periodic player inventory captures are spread across the configured scan period and resolve current player objects before capture. Known ordinary block placements no longer schedule native container checks.

Update AntiGrief for [BlockData API 0.6.9](https://github.com/TheNINJALLO/endstone-blockdata-api/releases/tag/v0.6.9) on Endstone 0.11.15, BDS 1.26.60.6 (Minecraft 1.26.60), and CPython 3.14 on Linux x86-64. The capture, patch, and player inventory interfaces remain compatible; AntiGrief retains its existing native version handshake and service reconnect behavior.

Read the native bridge's `canonical` and `snbt` block-entity fields so snapshot metadata and container audit rows correctly identify canonical NBT, and SNBT appears in the WebUI for stored and inline snapshots. Older records using `canonical_nbt` and `raw_snbt` remain readable. Disabling `store_raw_snbt` now excludes both SNBT field names from queued container snapshots.

While the server is stopped, replace the older AntiGrief wheel with `endstone_antigrief-1.5.22-py3-none-any.whl`. Install the complete `endstone_blockdata_inspector-0.6.9-cp314-cp314-linux_x86_64.whl` from the BlockData deployment ZIP. It bundles and loads its matching native provider; remove older inspector wheels and standalone BlockData libraries. Preserve the existing database, configuration, and plugin data folders. Keep the qualified default `enable-script=true` setting. See [installation](docs/installation.md).

Validation: all 131 automated tests and CI Ruff checks pass locally on Python 3.11, including cache freshness/bounds, scan scheduling, quiet container logging, snapshot isolation, BlockData 0.6.9 compatibility, and the existing rollback, recovery, persistence, and browser regressions. A local 54-slot nested-bundle benchmark reduces the Python diff step from about 16 ms to 0.2–0.5 ms per call. This excludes native capture and does not measure live server tick time. See [validation](docs/validation/1.5.22.json). AntiGrief 1.5.22 has not been validated on a running BDS 1.26.60.6 server or with live player transfers.
